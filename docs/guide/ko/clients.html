클라이언트

편집기, ash, 에이전트

모든 클라이언트는 같은 방법으로 커널에 닿습니다. 같은 컴퓨터의 매니저를 거치거나, 바깥에서는 전용 매니저를 거칩니다. 커널이 파일에 묶여 있으므로 모두 한 커널에서 만납니다.

에이전트와 셸

코딩 에이전트는 CLI를 씁니다. 같은 OS 사용자의 매니저를 찾거나 띄우므로 바이너리 말고는 토큰도 설정도 필요 없습니다. --detach와 logs --follow는 폴링하는 에이전트에 맞고, 종료 코드로 실행 결과를 알 수 있습니다.

VS Code와 IntelliJ 계획 #22

노트북 렌더러는 vscode-darkpyonix와 intellij-darkpyonix에 있습니다. .py와 .pynb를 셀로 보여 주고, 최신 실행 기록을 셀에 맵핑하며, 같은 컴퓨터의 매니저와 통신합니다. 작업은 매니저 마일스톤(M2) 뒤에 시작하고 #22에서 추적합니다. 그때까지는 파일을 코드로 열고 터미널에서 CLI를 씁니다.

ash 계획 #20

darkpyonix-ash는 Starboard를 포크한 공유 브라우저 노트북입니다. 공유 링크를 받은 사람은 링크에 담긴 권한으로 브라우저에서 커널을 엽니다. 매니저는 ash를 서빙하지 않고 커널 접근만 줍니다. ash는 darkpyonix.dev가 호스팅합니다(허브 참고). 공유 토큰으로 커널을 여는 작업은 #20에서 추적합니다.

Ember

darkpyonix-ember는 대화 우선 워크벤치입니다. Ember 서버는 각 컴퓨터의 매니저 API를 불러 실행 상태와 최신 출력을 보여 줍니다. 커널 스택은 대화, 계정, 컴퓨터 전환을 알지 못합니다.

여러 클라이언트 동시 접속

매니저 여러 개가 한 커널에 붙을 수 있고, 각자 같은 이벤트를 받습니다. 공유 문서(셀, 버전, 잠금, 접속자)는 커널이 들고 있습니다. 클라이언트가 셀을 고치면 파일에 저장됩니다. 디스크의 파일이 바뀌면(에이전트의 편집, git checkout) 커널이 1초 안에 다시 읽고 모든 클라이언트에 알립니다.
