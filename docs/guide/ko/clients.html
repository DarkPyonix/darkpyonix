클라이언트

편집기, ash, 에이전트

모든 클라이언트는 같은 방법으로 커널에 닿습니다. 같은 컴퓨터의 매니저를 거치거나, 바깥에서는 전용 매니저를 거칩니다. 커널이 파일에 묶여 있으므로 모두 한 커널에서 만납니다.

에이전트와 셸

코딩 에이전트는 CLI를 씁니다. 같은 OS 사용자의 매니저를 찾거나 띄우므로 바이너리 말고는 토큰도 설정도 필요 없습니다. --detach와 logs --follow는 폴링하는 에이전트에 맞고, 종료 코드로 실행 결과를 알 수 있습니다.

VS Code와 IntelliJ 계획 #22

노트북 렌더러는 vscode-darkpyonix와 intellij-darkpyonix에 있습니다. .py와 .pynb를 셀로 보여 주고, 최신 실행 기록을 셀에 맵핑하며, 같은 컴퓨터의 매니저와 통신합니다. 작업은 매니저 마일스톤(M2) 뒤에 시작하고 #22에서 추적합니다. 그때까지는 파일을 코드로 열고 터미널에서 CLI를 씁니다.

ash 계획 #20

darkpyonix-ash는 Starboard를 포크한 공유 브라우저 노트북입니다. 공유 링크를 받은 사람은 링크에 담긴 권한으로 브라우저에서 커널을 엽니다. 매니저는 ash를 서빙하지 않고 커널 접근만 줍니다. ash는 darkpyonix.dev가 호스팅합니다(허브 참고). 공유 토큰으로 커널을 여는 작업은 #20에서 추적합니다.

Ember

darkpyonix-ember는 대화 우선 워크벤치입니다. Ember 서버는 각 컴퓨터의 매니저 API를 불러 실행 상태와 최신 출력을 보여 줍니다. 커널 스택은 대화, 계정, 컴퓨터 전환을 알지 못합니다.

여러 클라이언트 동시 접속

매니저 여러 개가 한 커널에 붙을 수 있고, 각자 같은 이벤트를 받습니다. 공유 문서(셀, 버전, 잠금, 접속자)는 커널이 들고 있습니다. 클라이언트가 셀을 고치면 파일에 저장됩니다. 디스크의 파일이 바뀌면(에이전트의 편집, git checkout) 커널이 1초 안에 다시 읽고 모든 클라이언트에 알립니다.

협업은 2025 WebSocket 동기화(GET /api/ws/kernels/{kernel_id}?token=...)로 합니다. 클라이언트가 코드, 기록, 잠금을 요청하면 커널이 셀 잠금, 포커스, 실행 이벤트를 알립니다. 소켓에는 커널이 직접 답하고, 보내는 내용은 토큰의 능력으로 걸러집니다. PR #84에서 들어갔습니다.

변경 중

매니저가 소켓을 커널에 넘겨 매니저가 끝나도 스트림이 이어지게 하는 일은 아직 마무리 중입니다 변경 중 #47. TLS나 HTTP/2 위의 WebSocket은 아직 확인하지 못했고, 기록의 실행과 셀 대응은 인덱스 기준입니다 열림 #49.

공유 권한

전용 매니저는 darkpyonix share FILE --capabilities ...으로 커널마다 공유 토큰을 발급합니다. 토큰은 능력 다섯 개의 집합을 가집니다. 순서도 등급도 없습니다. 매니저는 작업마다 그 작업에 필요한 능력 하나가 집합에 있는지만 보고, 없으면 403으로 답합니다. PR #84에서 들어갔고, 일부 항목은 이슈 #49에 남아 있습니다.

능력뜻필요한 작업
read코드 보기커널 목록과 상태, 셀 코드, 이벤트 스트림과 WebSocket 연결, 접속자 표시와 포커스
history실행 기록과 출력실행 기록 목록과 내용, 문서와 스트림의 출력, 변수 목록, 실행 대기 결과
execute실행과 인터럽트실행, 인터럽트, 대기 실행 취소, 커널 시작, 재시작, 종료
edit코드 수정, 셀 잠금셀 생성, 수정, 삭제, 이동, 잠금과 해제, start_typing
manage공유 설정공유 목록, 발급, 철회

매니저 마스터 토큰과 커널 자신의 로그인 토큰은 다섯을 모두 가집니다. 코드 실행과 코드 수정은 다른 능력이어서, read,execute 토큰은 실행할 수 있지만 잠그거나 고칠 수 없습니다. 요청은 user_permission에 그 작업에 필요한 능력 이름을 실을 수 있습니다(2025 "write"는 실행에서는 execute, 셀에서는 edit, 공유의 "admin"은 manage). 다른 값은 400이고, 허락은 토큰의 집합이 정합니다.

변경 중

커널 시작, 재시작, 종료를 execute에, 변수 목록을 history에 둔 것은 임시이고 프로젝트 소유자가 다시 검토할 예정입니다.
