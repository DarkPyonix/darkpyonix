Getting started

Install and first run

You need two things: the darkpyonix binary, which is the CLI and the manager, and a Python 3.8 or newer interpreter for the kernel. The interpreter does not need DarkPyonix installed.

Get the CLI

The CLI and the manager are one Rust binary, darkpyonix. It carries the kernel's Python sources inside it and unpacks them into ~/.darkpyonix/runtime/ on first use, so the binary alone is enough to run kernels.

Prebuilt binaries are not published yet planned. The plan is a wheel that carries the binary (INTENT D10). Until then, build it from a checkout. This needs a stable Rust toolchain.

Put darkpyonix/manager/target/release/darkpyonix on your PATH.

The runtime API

Inside a kernel, import darkpyonix always works, because the kernel puts its own sources on sys.path. You install the package only to run a notebook outside a kernel, for example with python train.py in CI.

Release status

Version 0.2.0 is not on PyPI yet planned #46. PyPI still serves 0.1.0, the 2025 package under the MIT license, which is not the runtime API this guide describes. Version 0.2.0 is published under Apache-2.0 when a GitHub release is made after pull request #46 lands (issue #45). The package is standard library only and has no dependencies.

Choose the interpreter

A kernel runs on the interpreter chosen when it starts, in this order: --python PATH, then the DARKPYONIX_PYTHON environment variable, then python3 or python on PATH. The kernel keeps that interpreter until it is shut down, so --python matters only when the kernel is not running yet.

A first run

Any .py file works. A file with # %% cell markers gets per-cell outputs and per-cell run logs (see Notebook files).

The first run finds no manager, starts an ephemeral one, and the manager starts the kernel. The second run reuses both. If the first run is still going, the second is refused with exit code 75 and a hint to use --queue or stop. That is deliberate: two runs of one file in one process would share and corrupt state.

Afterwards the file has a sibling folder __runs__/train.py/ with one .ipynb per run. Run logs explains it.

Where things are kept

Per-user state lives in ~/.darkpyonix/. Set DARKPYONIX_HOME to move it, for example in tests.

PathWhat
user.keyThe key kernels and managers of the same OS user authenticate with. Mode 0600, created on first use. Being removed: the kernel will admit only the same OS account, checked by the peer identity the OS reports changing #55
locks/<kernel_id>.lockThe OS lock that keeps one kernel per file. The OS releases it when a kernel dies, so a stale file never blocks.
runtime/The kernel sources unpacked from the binary.
kernels/<kernel_id>.json, managers/<pid>.jsonRegistry files for discovery and for the CLI to find a manager. Being removed changing #50.
manager.dbHashed share tokens of a dedicated manager.
