Notebook files

A notebook is a Python file

Cells are comments and markdown is a function call, so python file.py runs the same code a kernel runs. Outputs never go into the file; they go into the run logs.

An example

Lines before the first marker are the preamble. The kernel runs it once, before any cell, in every run. Keep imports and the docstring there.

.pynb has the same syntax as .py. The extension only tells an editor to open the file as a notebook instead of as code. The kernel treats both the same.

Cell markers

  • A line starting with # %% opens a cell. The cell runs to the next marker or the end of the file.
  • [type] sets the cell type. Without it the cell is code.
  • A title may come before the type: # %% Load data [code].
  • The boundary syntax matches Jupytext's percent format. The difference is markdown: here it is a darkpyonix.markdown() call, not a comment.
  • The parser works line by line, like Jupytext, so a # %% line inside a triple-quoted string is still a marker.

Cell metadata

Lines of the form # @key: value right after a marker are that cell's metadata. A value that parses as JSON is used as JSON; otherwise it is a string. Unknown keys are kept and ignored.

Parameters

darkpyonix.params.get(name, default=..., choices=..., range=(min, max, step), type=..., help=...) reads a parameter. With choices, default is an index into the list. The value comes from the run request's params first, then from --name value on the command line, then from default. A value outside range or not in choices fails the cell with ValueError.

That is why the same file works both ways: darkpyonix run train.py --param lr=0.02 and uv run train.py --lr 0.02 set the same parameter.

Markdown

darkpyonix.markdown(text, silent=False) emits text/markdown in a kernel. With silent=True the text is shown but not written to the run log. Under python file.py it prints nothing, so the script's output does not change.
